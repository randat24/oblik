# Облік майна

Веб-застосунок для обліку майна підрозділу: що є, де воно, у кого на руках,
що поїхало на позицію й що не доїхало.

Працює у полі — з телефона, часто без стабільного зв'язку. Базою слугує
звичайна Google Таблиця: її бачать і правлять руками ті, хто до застосунку
не заходить взагалі, і це свідоме обмеження, а не тимчасове рішення.

**Стек:** Next.js 16 (Pages Router) · React 19 · Google Sheets API · Vercel
**Мова інтерфейсу:** українська · **Без клієнтських залежностей на стан** — усе на `useState`

---

## Навіщо це існує

До цього був Apps Script: банер Google згори, секунди на кожен клік, ніякого
свого домену. Головне — не було історії: хто, коли й що змінив, з'ясовувалося
за скріншотами в чаті.

Тепер це застосунок із власним доменом, входом за позивним, журналом кожної
зміни та кількома окремими робочими місцями — від складу до пункту збору посилок.
Таблиця лишилася на місці й лишається джерелом правди.

## Що вміє

| Розділ | Про що |
|---|---|
| **Пошук** | Живий, по всіх листах одразу: S/N, позивний, модель, місце, примітка. Групує знахідки за тим, як саме збіглося, і веде на потрібний рядок |
| **Листи майна** | Картки, фільтри, редагування на місці, «Видати» / «Прийняти», скасування видалення |
| **Склад** | Ящики з фото та QR-кодами; вміст ящика — окремими позиціями, з обліком узятого й поверненого |
| **Майно Рибаківки** | Великий склад із рухом: приймання, списання, залишок |
| **Доставки** | Посилка з кількох місць, кожне зі своєю вагою, датою та пріоритетом; втрати з причиною; маршрут «зібрано → водій → точка вильоту → позиція» |
| **Пункт збору** | Окрема сторінка за посиланням для того, хто пакує: дві дії й нічого зайвого |
| **Звірки** | Перевірка наявності з телефона: кожна позиція пишеться одразу, застосунок можна закрити й повернутися |
| **Акти** | Хто віддав, хто прийняв, у якому стані |
| **Журнал** | Кожна зміна: дата, час, лист, рядок, «було → стало», хто |
| **Дашборд** | Скільки де лежить, що застрягло довше за норму, що першочергове |

Плюс особистий розділ `/health` — окремий модуль, який навмисно ніде не
перетинається з рештою застосунку (див. нижче). Усередині нього — курс
програмування на 50 уроків із пісочницею просто на сторінці (основи →
React → сервер), довідник, розбори коду цього ж застосунку та щоденник
практики.

## Як це влаштовано

Найцікавіше в проєкті — не список екранів, а обмеження, під які довелося
підлаштовувати архітектуру.

### Google Таблиця як база даних

Таблицю правлять руками, паралельно із застосунком. Звідси три правила, які
тримають усе інше:

**Колонки шукаються за заголовками, а не за номерами.** Людина може переставити
стовпці місцями — застосунок це переживе:

```js
// lib/sheets.js
export function findColumns(header) { /* «де», «где», «розташування» → одна колонка */ }
```

**Нові поля дописуються тільки в кінець.** Індекси всередині модулів позиційні,
тож нова колонка не має зсувати те, що вже лежить у таблиці:

```js
// lib/stock.js
// «Облік» дописано в кінець навмисно: індекси колонок позиційні, тож нове
// поле не має зсувати те, що вже лежить у таблиці
export const STOCK_HEADERS = [ /* …, */ 'Оновлено', 'Облік' ];
```

**Заголовки лікують себе самі.** Якщо лист створений старою версією й коротший
за поточну схему — рядок заголовків дописується при першому читанні, один раз
на процес і без падіння, якщо не вийшло. Міграцій немає, бо їх нікому запускати.

### Сесія без бази

Ніякого сховища сесій: cookie містить підписаний HMAC-SHA256 payload, і цього
досить, щоб дізнатися позивний і роль. Перевірка підпису — `timingSafeEqual`.

Термін життя прив'язаний не до моменту входу, а до годинника:

```js
// lib/auth.js
/** Довжина вікна сесії: 00:00, 04:00, 08:00 і так далі за київським часом */
export const WINDOW_HOURS = 4;
```

Усі виходять з системи одночасно, о рівній годині. Загублений телефон
перестає бути ключем максимум за чотири години, і не треба нікому пояснювати,
коли саме «спливе» його вхід.

### Хто саме змінив — без протягування «хто» крізь усі виклики

Журналу треба знати автора, а автор відомий тільки на вході в маршрут.
Замість зайвого аргументу в кожній функції — `AsyncLocalStorage`:

```js
// lib/auth.js
const actorStore = new AsyncLocalStorage();
export function currentActor() { return actorStore.getStore()?.actor || ''; }
```

`withAuth` кладе туди позивний, `logChange` дістає його на будь-якій глибині.

### Доступ за посиланням

Дві речі мають працювати без пароля до сайту: пункт збору `/zbir` і приймання
даних із «Команд» на iPhone. Обидві захищені однаково — довгим ключем у
посиланні, який порівнюється за сталий час:

```js
// lib/auth.js
export function sameSecret(a, b) {
  if (typeof a !== 'string' || typeof b !== 'string' || a.length !== b.length) return false;
  let diff = 0;
  for (let i = 0; i < a.length; i++) diff |= a.charCodeAt(i) ^ b.charCodeAt(i);
  return diff === 0;
}
```

Немає змінної з ключем — немає й маршруту: `/api/pack` відповідає 404, а не
«потрібен ключ». Те, чого не існує, не приваблює спроб підібрати.

Сам пункт збору — не урізаний інтерфейс поверх спільного API, а окремий
маршрут із рівно двома діями (`add` і `handed`) та власним поглядом на дані:
видно лише свіже, редагувати чуже неможливо.

### Офлайн

У полі зв'язку може не бути, а внести треба зараз. Записи, які не пішли,
лягають у чергу в браузері й відправляються самі, щойно мережа повернеться;
читання підстраховане останньою вдалою відповіддю, щоб не показувати
порожній екран (`lib/offline.js`).

### PIN, якого немає в таблиці

Доступ до самої таблиці не має давати змоги зайти чужим позивним, тому в
листі «Люди» лежить не PIN, а його солений відбиток (`lib/people.js`).

### Ізольований особистий розділ

`/health` — власні листи, за бажанням власна таблиця, власний маршрут.
Ці дані не з'являються ні в пошуку, ні в журналі, ні на дашборді, ні в
переліку листів — не тому, що приховані з інтерфейсу, а тому, що інші модулі
про них не знають.

### Чиста логіка окремо від екрана

Розрахунки живуть у модулях без React і без читання таблиць — щоб їх можна
було перевірити окремо й правити, не чіпаючи сторінку:

- `lib/delivery.js` — місця, ваги, пріоритети, втрати, черга на дорогу
- `lib/weight.js` — тренд ваги, прогноз, чи сходиться дефіцит
- `lib/mult.js` — порядок прикладів у тренажері множення
- `lib/code.js`, `lib/ref.js`, `lib/tour.js` — зміст курсу, довідник, розбори коду
- `lib/practice.js` — щоденник практики: серія днів, підсумки, підказки

Курс усередині `/health` має власну пісочницю. Звичайний JavaScript
виконується у Web Worker — нескінченний цикл у чужому коді підвішує
воркер, а не сторінку. Сторінкові й React-завдання йдуть у рамку без
`allow-same-origin`, тож доступу ні до кукі, ні до застосунку в них немає.
Для React у рамку підвантажується зібраний файл із React і перетворювачем
JSX (`scripts/build-sandbox.mjs`) — React 19 більше не постачає готових
збірок для браузера.

## Структура

```
lib/       робота з таблицями та чиста логіка (без React)
pages/     сторінки
pages/api/ маршрути; кожен — під withAuth
public/    іконки, service worker, скріншоти довідки
scripts/   збірка пісочниці для уроків React
styles/    один globals.css, без CSS-модулів і без Tailwind
tests/     node --test, без залежностей
docs/      розгортання з нуля
```

## Запуск

```bash
cp .env.example .env.local   # і вписати значення
npm install
npm run dev                  # http://localhost:3000
```

Повне розгортання з нуля — [`docs/setup.md`](docs/setup.md).
Перелік змінних оточення з поясненнями — [`.env.example`](.env.example).

## Тести

```bash
npm test
```

203 тести на чисту логіку — доставки, вага, тренажер множення, курс,
щоденник практики. Серед них — перевірка, що кожне рішення уроку справді
розвʼязує своє завдання, а не просто гарно виглядає.

Залежностей на запуск немає: вбудований у Node runner (`node --test`).
Що саме покрито й чому не покриті маршрути — [`tests/README.md`](tests/README.md).

## Безпека

- Вхід за паролем (`APP_PASSWORD`) + позивний із PIN; сесія у HttpOnly-cookie,
  вікно — 4 години за київським часом
- PIN зберігається відбитком, не текстом
- Ключ сервісного акаунта — лише у змінних оточення, у код не потрапляє
- Фото лежать на Google Диску нерозшареними; показує їх `/api/photo` тільки
  тому, хто увійшов
- Керування людьми — лише для ролі «адміністратор»
- Публічні маршрути живуть за окремими ключами й вимикаються видаленням змінної
- Репозиторій приватний
