# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Equipment-accounting web app for a military unit ("Облік майна"): Next.js 16 Pages Router, React 19, plain JS (no TypeScript), deployed on Vercel. A Google Spreadsheet is the only database. People also edit that spreadsheet by hand, alongside the app, and that is deliberate. The app is used from phones in the field, often offline. UI text, error messages, code comments, commit messages and test names are all in Ukrainian; keep new ones in Ukrainian. Comments in this codebase explain *why* (often citing the incident that caused the code), so match that density and tone.

`README.md` is the main architecture write-up; `docs/setup.md` covers deploying from scratch, `docs/rotate.md` covers key rotation, and `.env.example` describes every env var and what turns off without it.

## Commands

```bash
npm run dev            # dev server (predev builds the React sandbox first)
npm run build          # production build (prebuild runs scripts/build-sandbox.mjs)
npm run lint           # eslint; CI fails on errors, warnings are allowed
npm test               # node --test 'tests/*.test.mjs', no extra deps
npm run test:watch
node --test tests/auth.test.mjs                        # one file
node --test --test-name-pattern="adminOnly" tests/auth.test.mjs   # tests matching a name
```

CI (`.github/workflows/test.yml`, Node 22) runs lint → test → build on every push and PR. Lint exists mainly for `no-undef`: a missing function once broke saving in production for weeks without any test or build noticing.

`public/vendor/react-sandbox.js` is generated by `scripts/build-sandbox.mjs` (React + ReactDOM + sucrase bundled for the in-page React lessons in `/me`). Never edit it by hand.

## Architecture

**Spreadsheet as DB** (`lib/sheets.js`): `SHEET_CONFIGS` lists the tabs the main app manages; each has a `kind` (`items`, `ledger`, `stock`, `warehouse`), and the kind decides which API route and view handle it. Rules that hold everything together:
- Columns in `items` sheets are found by **header text** (`findColumns`), not position, because people reorder columns by hand.
- Modules with positional schemas (e.g. `STOCK_HEADERS`, `PEOPLE_HEADERS`, `LOG_HEADERS`) only ever **append new columns at the end**.
- Headers self-heal: `ensureSheet` and the module readers create or extend header rows on first read. There are no migrations.
- Sheets API quota errors are retried with backoff (`lib/quota.js` `withRetry`) and shown as friendly 429s.
- Env vars are baked in at build time on Vercel: changing one requires a **Redeploy**, not just a Promote.

**Auth** (`lib/auth.js`, `pages/api/login.js`, `lib/people.js`):
- Login is either the shared `APP_PASSWORD` (admin) or a callsign + PIN. PINs are stored as salted HMACs in the «Люди» sheet, never as plain text.
- The session cookie is an HMAC-signed payload with no session store. It expires at fixed 4-hour Kyiv-time windows (`WINDOW_HOURS`), not a set time after login.
- Without `SESSION_SECRET`, login is disabled; there is no fallback secret.
- Without `APP_PASSWORD`, the app is open locally but nobody can get in on Vercel (`authRequired()`).
- Every API route is wrapped in `withAuth(handler, { adminOnly, openGet })`. It also runs the handler inside an `AsyncLocalStorage`, so `currentActor()` / `logChange()` know who made the change without passing it through every call.
- Write routes must check the sheet name from the request body against `SHEET_CONFIGS` via `sheetConfig(name, kind)`. «Люди» (roles), «Журнал» (audit log) and the personal sheets live in the same spreadsheet; without this check any logged-in user could promote themselves to admin.
- Two routes also accept a key from the link instead of a session: `/api/pack` (the `/zbir` packing page, key in `PACK_TOKEN`; a normal session works there too) and `/api/health-in` (iPhone Shortcuts, key in `HEALTH_INGEST_TOKEN`). Keys are compared in constant time. A route returns 404 when its env key is missing **or shorter than 16 characters**.
- `openGet` only lets anonymous `GET` requests through to the handler; it does not make the route read-only. The handler must keep its GET branch free of writes for guests and decide what they see via `isGuest()`. Only `/api/fund` uses it, for the shared fund page `/fond`.
- The "chief" (`isChief`) is a level above admin, used for irreversible delivery edits. Its callsign is the raw env `OWNER`, or else the raw env `HEALTH_OWNER`. `healthOwner()`'s code default (`'Fantomas'`) does not apply here, so with both vars unset there is no chief at all. It comes from env rather than the «Люди» sheet on purpose: anyone with spreadsheet access could otherwise grant it to themselves.

**Audit log** (`lib/log.js`): every change goes through `logChange` into the «Журнал» sheet (date, time, sheet, row, action, field, before → after, who).

**Client**: pages are very large single files (`pages/index.js`, `pages/me.js`) built with `useState` only, with no state library. There are two separate fetch wrappers; use the one the surrounding code uses:
- `components/base.js` `api()` is used by the main app (`index`, `fond`, `dostavka`, `reviziya`, `dupes-view`). When the network fails, it queues writes in localStorage (`lib/offline.js`) and replays them when the connection returns. Reads fall back to the last cached response.
- `components/util.js` `api()` is used by `/me`. It adds a 25 s timeout and a read-only mode (`setCanEdit`).

**Isolated personal section** (`/me`, `lib/health.js`, `/api/health*`): it has its own sheets, optionally its own spreadsheet (`HEALTH_SPREADSHEET_ID`). Other modules must not know about it: no search, log, dashboard or sheet-list integration. The routes `/api/health` and `/api/health-in` keep their old names on purpose, because iPhone Shortcuts call them.

## Shared fund (`/fond`)

`lib/fund.js` is the pure engine (no sheets, no React); `lib/fund-store.js` is the only code that talks to the three `Фонд — …` sheets; `pages/api/fund.js` is the route; `pages/fond.js` is the page (bottom nav + «Нова операція» sheet, UI pieces in `components/fund-ui.js`). Things that are easy to break:
- Money is **integer kopecks** everywhere in `lib/`. `kop()` parses, `money()` formats. Never use floats for amounts.
- The book is **append-only**: an operation is never edited or deleted, only cancelled with a reason (`status`, `cancelledAt`, `cancelReason`) and re-entered. Balances and cash are always replayed from the book (`compute`), never stored. `invariantOk` is the check shown to users.
- A period's `end` is **exclusive** (first day the person is out); vacation ranges are inclusive on both sides.
- An expense's participant list is stored explicitly and never recomputed. Auto mode (`mode: 'auto'`) is only for old rows. Day-split expenses (`periodFrom/periodTo`, `ranges`) take their days from `ranges`, which override group membership.
- Settings live in `Фонд — налаштування` as key/value (`openingCash`, `openingDiff`, `openingDate`, `excluded`, `owner`); `setConfig` updates in place. Free text and member rows are written with `raw: true` so `=…` never becomes a formula; keep that for any new write.
- New columns in `OP_HEADERS` go **only at the end**; `readFund` appends missing header cells itself (`ensureColumn`).
- `seedFund` only works on an empty fund. The owner action (`owner`) rewrites manual expenses by cancelling and re-adding them, new rows first, so a failure leaves a visible duplicate instead of a lost expense.
- Каса — це картка власника (`config.owner`): коли платить він, гроші йдуть із каси, а не «в плюс» йому. `ownerAsCash` (lib/fund.js) читає платника-власника як `cash` у `readFund`, API записує його як `cash`, у формі витрати його серед платників немає.
- Старий облік (таблиця «каса ВУ» до 15.10.2026) лежить **архівом**, а не операціями книги: `lib/fund-archive.js` (розбір і звірка, покритий тестами), `lib/fund-archive-data.js` (згенерований, руками не правити; збирає `scripts/build-fund-archive.mjs` з CSV, і падає, якщо рядки не сходяться з підсумками таблиці), вкладка «Звіти → Архів». Баланси від нього **не рахуються**: стан стартує зі знімка в `lib/fund-seed.js`, а тест `tests/fund-archive.test.mjs` стежить, щоб підсумки архіву й знімок збігались. У старій таблиці плюс означає «винен у касу», у застосунку навпаки (`toAppBalance`).
- Dates are `YYYY-MM-DD` strings. `components/date-picker.js` is the only date field (the native popup cannot be themed); its rules are in `lib/calendar.js`, and «today» is Kyiv time, not the user's clock.

## Quality checks worth re-running

- Accessibility: load a page in Playwright and run `axe-core` (`window.axe.run(document)`); the fund screens and the home page are clean. Keep `lang="uk"` in `pages/_document.js`, a `main` landmark and one `h1` per page.
- Підписи полів: форми писали як `<label>…</label><input/>` без звʼязку, тому `components/label-links.js` (підключений у `_app.js`) сам ставить `for`/`aria-labelledby` для підписів, що стоять поруч із полем, і для рядків картки (`.drow`). Нове поле з власним `aria-label` або `htmlFor` він не чіпає. Чипи-фільтри — це `<button class="chip">`, а не `div`.
- `npm audit --omit=dev` should show no critical/high findings; update `next`/`react` within their ranges rather than pinning old versions.
- Security headers are set in `next.config.js`. `X-Frame-Options` is `SAMEORIGIN`, not `DENY`, because the lesson sandbox iframe in `/me` is same-origin. The camera is the only permission the app needs.
- A render crash shows `components/error-boundary.js` (wrapped in `pages/_app.js`) instead of a white screen; `pages/404.js` is the custom 404.

## Tests

`tests/README.md` sets the conventions:
- Only pure logic in `lib/` is tested; `pages/api/*` and pages are deliberately not covered, because they depend on the live spreadsheet. If a route gains logic worth testing, move that logic into `lib/` first.
- One test makes one behavioural claim, and its name states what must be true.
- Describe rows by field name via `tests/helpers.mjs`, not array positions.
- Pin time to fixed values (e.g. `NOW` from `tests/helpers.mjs`), or tests start failing on some unexpected day.
- Check that a new test can fail: break the line it guards and confirm `npm test` goes red.
