# Тести

```bash
npm test          # один прогін
npm run test:watch # перезапуск при зміні файлів
```

Залежностей немає: це вбудований у Node runner (`node --test`), доступний з
Node 18. Ставити нічого не треба, на збірку це не впливає.

## Що покрито

Тільки чиста логіка — модулі без React і без читання Google Таблиць:

| Файл | Про що |
|---|---|
| `delivery.test.mjs` | місця, ваги, черговість, втрати, застрягле, читання й запис рядка листа |
| `weight.test.mjs` | згладжування, швидкість, прогноз, темп, пояснення стрибків, збіг раціону з вагами |
| `mult.test.mjs` | уроки, рівні повторення, підбір завдань на день, правильність питань |

Маршрути `pages/api/*` і сторінки не покриті навмисно: там усе впирається в
живу таблицю, і тест перетворився б на перевірку заглушок замість логіки.
Якщо в маршруті зʼявляється розрахунок, який хочеться перевірити, — його
місце в `lib/`, а не в обробнику.

## Як писати нові

Один тест — одне твердження про поведінку, а назва каже, що саме має бути
правдою: «втрачене не висить у лишилось», а не «тест функції partsOf».
Через півроку саме назва пояснює, навіщо цей рядок коду.

Дані описуються іменами полів, а не позиціями в масиві — для цього є
`tests/helpers.mjs`:

```js
import { sheet } from './helpers.mjs';

const list = parseDeliveries(sheet(
  { what: 'Вода', parts: 'А; Б; В', partsDone: '1; 2' },
));
```

Час завжди фіксований (`NOW`, `at(20)`), інакше тест почне падати в
неочікуваний день.

## Чи ловлять вони щось

Перевірити просто: зіпсуйте рядок у `lib/` і запустіть `npm test`. Якщо
все зелене — тест перевіряє не те. Наприклад, прибрати `&& !x.lost` із
`partsOf` — падають два тести, замінити `return null` на `return 0` у
розборі ваги — падає один.
