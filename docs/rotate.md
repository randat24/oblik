# Заміна ключів

Ключ, який кудись потрапив, — уже не ключ. Не «майже безпечно» й не «навряд
чи хтось скористається»: він або відомий лише вам, або його треба міняти.

Потрапити він може куди завгодно й непомітно: у листування, у знімок
екрана, у чат із помічником, у скріншот налаштувань, у надісланий колезі
файл. Це не привід себе картати — це привід мати під рукою цю сторінку й
за пів години все замінити.

Загальне розгортання — у [setup.md](setup.md).

---

## Головне, що ламає всі заміни

**Vercel підставляє змінні під час збірки, а не під час роботи.** Змінили
значення в налаштуваннях — застосунок про це не знає, доки не зберете
заново. Це найчастіша причина «я ж замінив, а воно все одно старе».

Тому кожна заміна нижче закінчується однаково:

1. Vercel → Settings → Environment Variables → змінити значення
2. Deployments → останній → **Redeploy**
3. Відкрити сайт і переконатись, що працює
4. І аж тоді прибрати старий ключ там, звідки він видається

Порядок саме такий. Приберете старий ключ першим — застосунок ляже між
кроками, і ви лагодитимете вже поспіхом.

---

## Що з чим пов’язано

| Змінна | Що відкриває | Де міняти |
|---|---|---|
| `GOOGLE_PRIVATE_KEY`, `GOOGLE_SERVICE_ACCOUNT_EMAIL` | читання й запис усієї таблиці | Google Cloud Console |
| `GOOGLE_OAUTH_CLIENT_SECRET`, `GOOGLE_OAUTH_REFRESH_TOKEN` | завантаження фото на Диск від вашого імені | Google Cloud Console |
| `APP_PASSWORD` | вхід у застосунок | вигадуєте самі |
| `SESSION_SECRET` | підпис сесій — ним підробляють вхід | вигадуєте самі |
| `HEALTH_INGEST_TOKEN` | запис у особистий розділ ззовні | вигадуєте самі |
| `PACK_TOKEN` | сторінка пакування без входу | вигадуєте самі |
| `SPREADSHEET_ID`, `HEALTH_SPREADSHEET_ID` | не ключі, а адреси — див. окремо нижче | — |

## 1. Ключ сервісного акаунта — найважливіший

Це повний доступ до таблиці: читати, писати, стирати. Якщо міняти лише
одне — міняйте це.

1. https://console.cloud.google.com/ → ваш проєкт
2. **APIs & Services → Credentials** → сервісний акаунт `oblik`
3. Вкладка **Keys** → **Add key → Create new key → JSON** — завантажиться новий файл
4. З нього знадобиться поле `private_key`
5. Vercel → `GOOGLE_PRIVATE_KEY` → вставити нове значення

   Вставляйте разом із рядками `-----BEGIN PRIVATE KEY-----` і
   `-----END PRIVATE KEY-----`, як описано в [setup.md](setup.md).
6. **Redeploy**, відкрити сайт, переконатись, що дані читаються
7. І лише тепер: Keys → старий ключ → **Delete**

`GOOGLE_SERVICE_ACCOUNT_EMAIL` міняти не треба — пошта акаунта лишається
та сама. Доступ до таблиці теж лишається: він виданий пошті, а не ключу.

## 2. OAuth для фото

Тут дві речі, і вони пов’язані: відкликання таємниці клієнта робить
недійсними всі видані нею оновлювальні токени.

1. Console → **Credentials** → ваш OAuth client → **Reset secret**
2. Vercel → `GOOGLE_OAUTH_CLIENT_SECRET` → нове значення
3. Пройти вхід заново, щоб отримати новий `GOOGLE_OAUTH_REFRESH_TOKEN`
   (маршрут `/api/oauth/start` у самому застосунку)
4. Vercel → `GOOGLE_OAUTH_REFRESH_TOKEN` → нове значення
5. **Redeploy** → перевірити, що фото завантажується

Поки це не зроблено, застосунок працює — не працюватиме лише
завантаження фото.

## 3. Пароль входу

`APP_PASSWORD` — те, що набирають на вході. Міняється просто, але про це
треба сказати всім, хто ним користується, і сказати **не тим самим
каналом**, яким ключ витік.

Vercel → `APP_PASSWORD` → нове значення → **Redeploy**.

## 4. Підпис сесій

`SESSION_SECRET` — ним підписані печива входу. Хто його знає, той може
підробити вхід під будь-яким позивним, включно з адміністратором.

Vercel → `SESSION_SECRET` → новий довгий випадковий рядок → **Redeploy**.

Після заміни **всіх вигонить із застосунку**: старі печива підписані
старим ключем і перестають бути дійсними. Це не поломка — це і є те, чого
ви хотіли. Але робіть це тоді, коли повторний вхід нікому не зіпсує
роботу.

Новий рядок можна взяти будь-де, головне — довгий і випадковий:

```
node -e "console.log(require('crypto').randomBytes(32).toString('base64url'))"
```

Порожній або залишений `change-me-in-env` вимикає вхід зовсім — застосунок
про це скаже прямо, а не вдаватиме, що працює.

## 5. Токени розділів

`HEALTH_INGEST_TOKEN` — ним пишуть в особистий розділ ззовні (годинник,
скорочення). `PACK_TOKEN` — ним відкривається сторінка пакування без
входу.

Обидва — просто довгі випадкові рядки, тією ж командою, що й вище. Після
заміни треба вписати новий токен там, звідки ним користуються: у
скороченні на телефоні, у закладці на сторінку пакування.

## 6. Адреси таблиць — не ключі

`SPREADSHEET_ID` і `HEALTH_SPREADSHEET_ID` — це не таємниця, а адреса. Сама
по собі вона нічого не відкриває: доступ до таблиці має лише той, кому ви
його видали.

Але якщо адреса відома, а доступ колись був виданий зайвому — забирати
треба доступ, а не адресу: Google Таблиці → **Доступ** → прибрати зайвих.

Змінити сам ідентифікатор можна лише разом із таблицею: створити нову,
перенести листи, видати доступ роботу, поміняти змінну. Це робота на
годину, і вона майже ніколи не потрібна.

## Після заміни

Перевірте, що працює саме те, чого торкались:

| Замінили | Перевірте |
|---|---|
| ключ сервісного акаунта | головна відкривається, список речей видно |
| OAuth | фото на складі завантажується |
| `APP_PASSWORD` | вхід із новим паролем |
| `SESSION_SECRET` | вас вигнало, новий вхід працює |
| `HEALTH_INGEST_TOKEN` | запис ззовні доходить |
| `PACK_TOKEN` | сторінка пакування відкривається за посиланням |

І окремо: у репозиторії ключів немає й ніколи не було — `.env` і
`.env.local` у `.gitignore`, а `.env.example` містить лише назви змінних
із порожніми значеннями. Перевірити це можна будь-коли:

```
git ls-files | grep -E "^\.env"
```

Має вивести рівно один рядок — `.env.example`.
